Группа: ИТ-9.24.2

Что сделано: нарисовал путь изменения формы заявки, расписал роли, нашёл место где ошибка может пройти незамеченной.

Схема:

```
идея -> правка кода (index.html, app.py) -> commit в ветку -> PR в main -> тесты в CI
-> сборка образа -> docker compose up -> проверка в браузере (отправить заявку, получить номер)
-> пользователь -> логи и /health -> если что-то сломалось, обратно к правке кода
```

Роли:
- разработчик - меняет код, делает PR, чинит если тесты упали
- тестировщик - пишет тесты, проверяет что заявка реально отправляется
- эксплуатация - запускает сервис, смотрит логи и статусы, поднимает если упал

Где ошибка может остаться незамеченной: виды неисправностей записаны в двух местах - в форме (option value в index.html) и в API (KINDS в app.py). Если поменять value в форме и забыть про app.py, API будет отвечать 400 и заявка не отправится. Тесты это не поймают, потому что они шлют запросы сразу в API с готовыми значениями и форму вообще не читают. Проверил: поменял value="screen" на value="display", тесты всё равно прошли (Ran 7 tests, OK).

Какую проверку добавить: тест, который берёт значения option из index.html и проверяет что каждое есть в KINDS и API отвечает на него 201.

Ответ на вопрос (почему готовый код ещё не значит работающий сервис): код надо ещё собрать, запустить с правильными настройками (порты, адрес api, том для данных), и web должен достучаться до api. Ошибка может быть на любом шаге, даже если код правильный. Работает сервис или нет, видно только когда пользователь реально получил номер заявки.
