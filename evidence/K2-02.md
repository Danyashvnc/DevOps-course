Написал lab/Dockerfile по шаблону, собрал образ devops-student:v1 и запустил из него web на 8081.

```
FROM python:3.13-slim-bookworm
LABEL course.student="Danyashvnc"
WORKDIR /app
ENV PYTHONUNBUFFERED=1 PYTHONDONTWRITEBYTECODE=1
COPY app.py index.html ./
RUN mkdir -p /data && chown 10001:10001 /data
USER 10001:10001
EXPOSE 8000
CMD ["python", "app.py"]
```

Базу взял ту же что в bootstrap, python 3.13 slim. В LABEL мой код. COPY берёт app.py и index.html из папки lab, она в команде сборки указана как контекст, и кладёт в /app. CMD запускает python app.py при старте контейнера.

С /data так: приложение работает от 10001 (USER), а папку создаёт RUN ещё от root. Поэтому сразу делаю chown на 10001, иначе api потом не сможет записать туда requests.sqlite.

EXPOSE 8000 я оставил как пометку, порт он не открывает.

Вопрос: почему EXPOSE мало и зачем -p?
EXPOSE просто записывает в образ номер порта, вроде документации. Связь с компьютером делает -p 127.0.0.1:8081:8000: порт 8081 у меня ведёт в 8000 в контейнере. Без -p браузер в контейнер не попадёт.
