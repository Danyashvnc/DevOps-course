# Работа K2-05

Группа: ИТ-9.24.2
Код студента: Danyashvnc

Поставил в compose.student.yaml у web API_URL на порт 9999, посмотрел что сломалось, вернул 8000.

```
compose.student.yaml, сервис web:
API_URL: http://api:9999

docker compose -f compose.student.yaml up -d web
web   Up (healthy)   127.0.0.1:8080->8000/tcp

curl http://localhost:8080/health
{"process": "running", "role": "web"}

curl -i http://localhost:8080/api/requests
HTTP/1.0 503 Service Unavailable
{"error": "upstream_unavailable", "request_id": "f1d1e026"}
```

Страница открывается и web healthy, но список заявок не грузится, пишет "Сервис заявок недоступен".

```
docker compose -f compose.student.yaml logs --tail=5 web
{"time": "2026-11-07T01:52:37.237890+00:00", "role": "web", "event": "upstream_unavailable", "request_id": "f1d1e026", "target": "http://api:9999", "error": "<urlopen error [Errno 111] Connection refused>"}
{"time": "2026-11-07T01:52:37.237957+00:00", "role": "web", ... "GET /api/requests HTTP/1.1\" 503 -"}
```

api работает и слушает 8000. web лезет в api на 9999, там пусто, отсюда Connection refused. Имя api при этом находится. В K1-03, когда api был остановлен, ошибка была другая: No address associated with hostname. Здесь контейнер на месте, порт не тот. Сам web живой, поэтому health 200, а всё что через api отдаёт 503.

Вернул 8000:

```
API_URL: http://api:8000

docker compose -f compose.student.yaml up -d web

curl -i http://localhost:8080/api/requests
HTTP/1.0 200 OK

POST /api/requests {"kind":"software"}
HTTP/1.0 201 Created
{"request": {"id": 7, "kind": "software", ...}}

лог api: {"event": "request_accepted", "request_id": 7}
```

Список снова грузится, заявка 7 принята. В итоговом compose.student.yaml стоит http://api:8000.

Одного сохранения файла мало: web берёт новый API_URL только после docker compose up -d web, compose при этом пересоздаёт контейнер.

Вопрос: 8080 или 8000?
8000. Через 8080 браузер заходит с моего компьютера в web. Внутри сети compose web ходит в контейнер api напрямую, а api слушает 8000.
