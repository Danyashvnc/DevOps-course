Добавил отдельный job build, он собирает docker образ после test. Проверил, что при упавшем тесте build не запускается.

```
build:
  runs-on: ubuntu-latest
  needs: test
  timeout-minutes: 10
  steps:
    - uses: actions/checkout@d23441a48e516b6c34aea4fa41551a30e30af803 # v6
      with:
        persist-credentials: false
    - run: docker build -f lab/Dockerfile -t devops-student:${{ github.sha }} lab
```

У build свой runner, файлов из test на нём нет, поэтому checkout стоит ещё раз, тот же action с тем же SHA что в шаблоне. needs: test пускает build только после успешного test. В тег я подставил ${{ github.sha }}, это SHA который обрабатывает run, по нему видно из какого коммита образ.

1) Сломал тест (201 на 200), build уже был в workflow.
Run: https://github.com/Danyashvnc/DevOps-course/actions/runs/42331311673, push, SHA 65c7476

```
test   failed  (AssertionError: 201 != 200)
build  skipped
```

build даже не стартовал.

2) Вернул 201.
Run: https://github.com/Danyashvnc/DevOps-course/actions/runs/42331449991, push, SHA 3dc6522

```
test   success (Ran 7 tests, OK)
build  success
naming to docker.io/library/devops-student:3dc652234d1cf8360f4db40c7a3192a881c27c34 done
```

В одном run прошли и test и build.

Без needs оба job запустились бы одновременно, хоть build и написан ниже. needs: test ставит барьер: образ собирается только из кода, который прошёл тесты.

Вопрос: где останется образ после удаления runner?
Нигде. Runner после job удаляется со всем содержимым, образ вместе с ним. Сохранить его можно было бы через docker push в registry, в моём workflow такого шага нет.
