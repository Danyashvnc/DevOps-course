Сделал compose.student.yaml, поднял на нём api и web из своего образа, создал заявку, пересоздал api и проверил что заявка осталась.

compose.student.yaml скопировал из compose.yaml и поменял image у двух сервисов:

```
diff compose.yaml compose.student.yaml
<     image: devops-course:base
>     image: devops-student:v1
(у api и у web)
```

```
docker compose stop
docker compose -f compose.student.yaml config
docker compose -f compose.student.yaml up -d
docker compose -f compose.student.yaml ps
devops-course-api-1   devops-student:v1   Up (healthy)   8000/tcp
devops-course-web-1   devops-student:v1   Up (healthy)   127.0.0.1:8080->8000/tcp
```

Оба на devops-student:v1.

Первая заявка:

```
POST /api/requests {"kind":"screen"}
{"request": {"id": 5, "kind": "screen", ...}, "instance": "3e7ca47a6ca5"}
```

Получила номер 5, потому что 1-4 остались с прошлых работ (том тот же).

```
docker compose -f compose.student.yaml up -d --no-deps --force-recreate api
id api до:    3e7ca47a6ca5
id api после: 64247b16dc93

GET /api/requests
{"requests": [{"id": 5, ...}, {"id": 4, ...}, {"id": 3, ...}, {"id": 2, ...}, {"id": 1, ...}], "total": 5, "instance": "64247b16dc93"}

POST /api/requests {"kind":"battery"}
{"request": {"id": 6, "kind": "battery", ...}, "instance": "64247b16dc93"}
```

id у api сменился, значит контейнер новый. Заявка 5 на месте, новая стала 6.

API_URL у web равен http://api:8000. По нему web ходит в api. Слово api тут имя сервиса: compose создал сеть devops-course_default, и в ней docker сам подставляет вместо api адрес контейнера.

Порты. Внутри оба контейнера слушают 8000. На мой компьютер проброшен только web: 127.0.0.1:8080 -> 8000. Я открываю localhost:8080 и попадаю в web, дальше web по сети compose стучится в api:8000. У api порта наружу нет.

Том requests подключён к api в /data, там файл requests.sqlite. Том живёт отдельно от контейнера. Новый контейнер api подключил тот же том и увидел старые заявки.

Как запустить:
1. docker build -f lab/Dockerfile -t devops-student:v1 lab
2. если работает обычный стенд, docker compose stop
3. docker compose -f compose.student.yaml up -d
4. docker compose -f compose.student.yaml ps, ждать пока api и web станут healthy
5. открыть http://localhost:8080 и отправить заявку
6. остановить: docker compose -f compose.student.yaml stop. down -v не делать, он сотрёт том с заявками

Вопрос: почему базу нельзя держать только в контейнере?
Всё что записано в контейнер, лежит в его слое. При пересоздании старый контейнер удаляется вместе со слоем, и база пропадёт, новый api начнёт с нуля. Том при этом остаётся, поэтому база в томе переживает пересоздание.
