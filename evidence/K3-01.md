Группа: ИТ-9.24.2

Расписал для своего проекта когда запускается проверка, какой тест, какая сборка и кто решает про выпуск. Нарисовал схему веток.

Запуск: Student CI срабатывает на push в любую ветку и на pull_request.
Тест: python -m unittest discover -s tests -p test_app.py. Он поднимает api и web и проверяет создание заявки, повтор без дубля, 503 при остановленном api и ещё пару вещей.
Сборка: docker build -f lab/Dockerfile -t devops-student:<sha> lab, идёт только после зелёных тестов.
Выпуск решает человек. Преподаватель смотрит PR, я после этого делаю merge. Зелёный CI сам ничего не выпускает.

```
main ──────────────────────────────●──────
  \                               /
   kt3 ──commit──commit──commit──┘
            │       │       │
         Student CI на каждый push (test -> build)
            │
         PR kt3 -> main (тоже запускает Student CI)
            │
         проверка преподавателем -> merge
```

Ветка живёт недолго: от main, сделал КТ, PR, после проверки merge. На следующую КТ новая ветка.

Про ошибку я узнаю через пару минут после push, в Actions: красный test или build. Это ещё до того, как кто-то откроет PR. Потом те же статусы видны в самом PR рядом с замечаниями.

CI, delivery и deployment. CI проверяет и собирает каждое изменение автоматом. При continuous delivery собранная версия в любой момент готова к выпуску, но кнопку жмёт человек. При continuous deployment выпуск тоже идёт сам после зелёных проверок. У меня только CI: тесты и сборка образа, образ никуда не уходит.

Git-flow держит две постоянные ветки main и develop и отдельные feature, release, hotfix. Это для команды с релизами по графику. У меня один человек и выпускать нечего, столько веток только запутает. С короткой веткой и PR в main шагов меньше, и проверка стоит в одном месте.

Вопрос: сборка образа это автоматический deployment?
Нет. Образ собирается на runner и пропадает вместе с ним. Deployment это запуск новой версии там, где ей пользуются. Я образ никуда не пушу и нигде не запускаю.
