Процесс: python app.py с PID 1, это главный процесс контейнера api, запущен от пользователя 10001 (не root, так задано в Dockerfile через USER).

Порт: 0.0.0.0:8000 - его слушает app.py. 127.0.0.11 это DNS докера, он к приложению не относится.

HTTP-ответ: 200 OK, в ответе role api, значит ответил именно api. Но /health показывает только что процесс жив, базу и заявки он не проверяет.

Лог: строки GET /health каждые 3 секунды это healthcheck из compose.yaml. А строка в 23:59:02 это мой curl - время совпадает с Date в ответе.

Связь: процесс app.py слушает порт 8000, curl пришёл на этот порт, процесс ответил 200 и записал это в лог.

Была проблема: при первом запуске порт 8080 был занят другим моим проектом, web поднялся без порта. Остановил тот проект и пересоздал web (docker compose up -d --force-recreate web), после этого всё заработало.

Ответ на вопрос (почему tools видит процессы api, а не все процессы компьютера): в compose.yaml у tools стоит pid: service:api и network_mode: service:api. То есть tools подключается к процессам и сети только контейнера api, остальное от него изолировано.
